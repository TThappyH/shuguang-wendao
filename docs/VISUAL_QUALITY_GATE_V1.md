# 《曙光问道》Visual Quality Gate V1

- 阶段：视觉表现与流畅度基线建立
- 适用版本：V6.7.2 启动修复候选
- 适用范围：浏览器运行时、Three.js 画面、HUD/弹层、战斗可读性、帧时间与资源计数
- 当前决策：门禁规则已落文档；候选运行时尚未通过门禁

## 1. 目标与边界

V1 只建立可复现的视觉质量门禁和性能基线，不新增玩法、不调整数值、不重构运行时。所有结论必须来自固定视口截图、浏览器运行记录或可重复的指标采样。

明确不做：

- V6.8 新玩法、Boss、地图、武器、法宝或路径扩展
- 大型特效、粒子系统、材质系统或渲染架构重构
- 与视觉门禁无关的清理、命名迁移、依赖升级
- 用主观描述替代截图、场景定义或指标

## 2. 视觉层级

### L1：主视觉符号

- 角色、主标题/版本身份、核心战斗反馈必须一眼可识别。
- 正式产品名统一使用“曙光问道”；旧产品名不得出现在主标题、角色名或主要 HUD。
- 角色轮廓、朝向和受击/冲刺状态不能因动画永久改变比例。

### L2：场景氛围

- 背景、地面、光照和环境装饰服务于角色与威胁识别。
- 环境对比度不得遮蔽敌人、Boss、危险区和掉落物。
- 暗色/亮色方案只能有一个最终主导层，禁止多套未清理的视觉主题互相覆盖。

### L3：战斗可读性

- 敌人轮廓、攻击方向、危险区、Boss 血条、命中和死亡反馈必须可区分。
- VFX 的优先级按“危险预警 > 命中确认 > 角色技能 > 环境装饰”排序。
- 高密度场景仍应能定位玩家、最近威胁和下一步移动区域。

### L4：节奏与反馈

- 起手、位移、受击、击杀、掉落、升级、暂停和 Codex 必须有清晰状态边界。
- 叠加反馈要有节奏，不得依赖持续堆叠透明 Mesh 形成噪声或资源增长。

## 3. Golden Scene 定义

所有场景使用固定视口 `1920x1080`、`1440x900`、`390x844`，记录 DPR、浏览器版本、资源加载结果。B/C/D 可以通过测试 harness 注入状态，但 harness 不得进入产品运行时代码。

### Scene A：启动与主视觉

- 冷启动进入菜单，展示标题、角色、背景、主按钮和主要装饰。
- 点击“踏入秘境”后 3 秒内进入可操作游戏。
- 验收：无 loader 错误；主标题/角色身份正确；主按钮可点击；三种视口无横向溢出；菜单到游戏没有残留遮罩。

### Scene B：常规战斗与路径共鸣

- 角色、至少三种武器、普通敌人、命中/击杀反馈、掉落和至少一条共鸣视觉同时出现。
- 验收：角色轮廓仍为第一视觉焦点；敌人和技能不混成同一颜色团；共鸣只强化反馈，不覆盖危险预警；HUD 与战场信息不互相遮挡。

### Scene C：高密度压力场

- 记录 80-100 个敌人、多个投射物、持续效果、危险区、掉落或共鸣场同时存在时的画面与指标。
- 验收：仍能分辨玩家、最近威胁、危险区和主目标；帧时间不出现不可解释的尖峰；重启后资源计数不持续增长。

### Scene D：Boss 预警与阶段反馈

- Boss 血条、Boss 名称/阶段、攻击预警、场地危险区、玩家技能同时出现。
- 验收：攻击预警先于伤害发生；Boss 与小怪轮廓分级；阶段变化可读；Boss HUD 不被事件 Banner 或移动端 HUD 遮挡。

## 4. 指标采样协议

每个场景在资源加载稳定后等待至少 2 秒，再采样 60 个 `requestAnimationFrame` 间隔。记录：

- `viewport`、`devicePixelRatio`
- 平均帧时间、P95 帧时间、由帧时间换算的 FPS
- `renderer.info.render.calls`
- `renderer.info.render.triangles`
- `renderer.info.memory.geometries`
- `renderer.info.memory.textures`
- 当前场景唯一材质数、`scene.children`
- `enemies`、`projectiles`、`effects`、`pickups`、`hazards`、共鸣场数量
- 浏览器 Console 错误、资源 404、WebGL 初始化结果

`dt` 若未由运行时暴露，必须写 `NOT_EXPOSED`，不可用估算值冒充。

## 5. V1 门禁阈值

阈值用于固定浏览器基线，不代表所有设备的性能承诺：

| 门禁 | 通过条件 |
|---|---|
| 启动 | 三次冷启动均能进入菜单；三次点击开始均能进入可操作游戏；无运行时异常 |
| 身份 | 主标题、角色名、版本身份统一为“曙光问道”；无旧名主视觉残留 |
| 视口 | `1920x1080`、`1440x900`、`390x844` 均无横向溢出，关键按钮可见可点击 |
| 动画 | 起手/冲刺/受击/死亡/掉落/弹层状态有明确进出；动画完成后不残留错误状态 |
| 战斗可读性 | Scene B/C/D 截图中玩家、主要威胁、危险区和主反馈可辨识 |
| 60Hz 帧时间 | Scene B/C/D 平均 FPS >= 55，P95 帧时间 <= 20ms；若浏览器刷新率高于 60Hz，仍按帧时间判定 |
| 移动端基线 | `390x844` 无横向溢出；Scene A 平均 FPS >= 45；弹层不遮蔽关闭控件 |
| 资源稳定性 | 冷启动与重启各 3 次后，`geometries`、唯一材质、`scene.children` 不单调增长；若增长必须有回收证据 |
| Console | 无应用异常、未处理 Promise、WebGL 错误；favicon 等非应用 404 单独记录 |
| 证据 | 每个 Golden Scene 有固定截图、指标记录、时间戳、测试来源和限制说明 |

## 6. 回归规则

- 与 `VISUAL_BASELINE_V1.md` 的同场景比较时，平均帧时间或 P95 帧时间增加超过 15% 自动进入复核。
- `renderer.info.memory.geometries`、唯一材质数或 `scene.children` 在相同状态下增加超过 15%，必须给出对象生命周期解释。
- 新增视觉效果必须说明层级（L1-L4）、触发状态、持续时间、回收方式和截图证据。
- 任何门禁失败都不得用“整体感觉更好”“应该没问题”关闭。

## 7. 通过与阻断

- `PASS`：全部硬门禁通过，证据齐全，且无未关闭的 P0/P1 视觉或生命周期问题。
- `PARTIAL`：规则、场景或部分指标已落地，但仍有门禁缺口；不得作为合并批准。
- `BLOCKED`：存在启动、状态机、身份、资源生命周期、关键可读性或性能证据阻断项。

初始 V6.7.2 候选按本规则为 `BLOCKED`。Runtime Closure Gate 已关闭身份、Codex/暂停状态、武器 Mesh 生命周期、玩家瞬时状态、Boss cooldown、Trail/命中碎片热路径和 gzip/browser loader 阻断；当前 closure rerun 为 `PARTIAL`，原因是高密度 isolated fixed-step 60Hz profile 的 P95 仍为 37.0ms，且远端 Review 尚未完成。

## 11. V6.7 Closure R2.1 supersession

R2.1 已用单命令 FAST LOOP 替代开发阶段重复 3000 帧 profile：同一 96-enemy high-density fixture 连续三次 600 帧 P95 为 `13.9 / 14.2 / 14.3ms`。随后唯一一次 3000 帧终测为平均 `12.646ms`、P95 `15.4ms`、P99 `18.8ms`，因此本节第 10 节中的旧 `37.0ms` 指标不再代表当前 runtime head。详见 `docs/V6.7_CLOSURE_R2.1.md`。
