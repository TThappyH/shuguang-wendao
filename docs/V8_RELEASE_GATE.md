# 《曙光问道》V8 Release Gate

## 目标

V8 不是把版本号改成 8，而是形成一条可完整跑通、可复盘、可继续平衡的单局循环：

`进入秘境 → 斩妖 → 升级/取舍 → 法宝与道途成型 → 境界突破 → Boss 推进 → 单局结算`

## 当前基线

- 基线分支：`dev/v8-foundation`
- V6.8 境界突破链：已实现并通过确定性浏览器回归
- 境界规则注册：15 条
- 境界链：炼气 → 筑基 → 金丹 → 元婴 → 化神 → 炼虚
- 旧版青曜 GLB：已接入实际游戏入口，作为当前角色资产
- V7.2 Boss 阶段闭环：6 个 Boss 均具备二相 / 真身状态、阶段预兆与一次性转阶段记录
- V7.3 单局闭环记录：升级选择、道途选择、Boss 时间、伤害/受伤与最终结算已接入运行记录
- main：不修改、不自动合并

## V8 必过门禁

### 1. 构建与启动

- `python tools/build_runtime_v6_7.py --check` 必须 PASS
- 真实 HTTP 入口可冷启动
- Three.js、GLTFLoader、GSAP 加载完成
- 青曜 GLB 状态为 `ready`
- 浏览器 Console Errors 为 0

### 2. 核心单局

- 玩家可以进入、移动、攻击、受伤、升级、暂停、重开
- 敌人持续生成，敌人和临时效果不会无限增长
- 6 条道途可识别、可组合、可在 HUD/图鉴中复盘
- 6 个 Boss 节点可按单局顺序推进
- 每个境界节点能触发突破选择并恢复战斗
- Boss 奖励、升级弹层、宝录和暂停弹层不会互相打穿状态机

### 3. 视觉与角色

- 实际游戏使用旧版青曜模型，不回退到积木角色
- 高马尾、白青袍色块、深色腿部和双剑轮廓在 55°~60° 镜头下仍可读
- 模型加载失败时必须有明确诊断，不得静默显示错误角色

### 4. 平衡与复盘

- 至少完成一轮完整单局记录
- 记录升级选择、道途组成、Boss 时间、伤害/受伤和结算结果
- 先有数据，再调整数值；不以单次顺利运行宣称平衡完成

### 自动化验收入口

```powershell
python tools/build_runtime_v6_7.py --check
python tools/test_v80_release_gate.py
```

`test_v80_release_gate.py` 会通过真实 HTTP 入口冷启动页面，等待 Three.js / GLTFLoader / GSAP 与青曜 GLB 就绪，检查移动、攻击、暂停、宝录、真实 XP 升级、五次境界突破、六个 Boss、奖励弹层、完整结算、记录导出入口以及浏览器 Console Errors。人工测试步骤见 [`docs/V8_HUMAN_TEST.md`](V8_HUMAN_TEST.md)，在通关或死亡结算页点击“导出本局记录”即可得到 JSON 复盘文件。

### 本地发布包

V8 可玩快照使用固定清单打包，并在写入后逐项做 ZIP 读回与 SHA-256 校验：

```powershell
python tools/package_v8.py
python tools/test_v8_package.py
```

默认产物为 `releases/v8-foundation-<git-head>.zip`。包内包含 `index.html`、已校验的 `runtime/v6.7`、旧版青曜 GLB、运行源码和 V8 审核文档；`PACKAGE_MANIFEST.json` 记录入口、分支、HEAD、文件大小与哈希。包仍需通过 HTTP 静态服务启动，并需要联网加载 CDN 上的 Three.js / GSAP。
